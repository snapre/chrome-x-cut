# Meta 高清图片选源

Threads 信息流会把适合卡片尺寸的 `currentSrc` 与更高清的 `srcset` 候选同时放在同一个图片节点上。当前扩展按 DOM 属性读取顺序保存，因此错误地优先选择带 `s640x640`、`p480x480` 等缩放参数的小图。

修复不修改 CDN URL，也不移除签名参数。URL 工具层只对页面已经提供的官方 CDN 候选评分：`stp` 中没有尺寸限制的候选优先；存在尺寸限制时按像素面积从大到小排列；无法识别时保持原顺序。内容脚本在创建候选前使用该排序，X 的 `name=orig` 行为保持不变。

单元测试覆盖无缩放、720、640、480 四类 Meta URL 的排序，并确认查询签名原样保留。
